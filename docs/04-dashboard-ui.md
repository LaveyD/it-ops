# 04 · 大屏 UI 设计

## 1. 首页布局（1920×1080 基准，等比缩放）

```
┌────────────────────────────────────────────────────────────────────┐
│ 顶栏:  Logo/标题  ·  日期时间  ·  设备在线率  ·  未确认告警  ·  拓扑版本  │
├─────────────────┬─────────────────────────────────┬────────────────┤
│ 左列（可滚动卡片组）│                                 │ 右列（可滚动卡片组）│
│                 │      网络拓扑（只读 GraphView）     │                │
│ ① 设备状态分布    │   3D 图标 + 分组 + 告警着色         │ ⑤ 实时告警滚动    │
│ ② 性能趋势       │   hover 浮层 / 点击穿透            │ ⑥ 设备 TOP N     │
│ ③ 业务系统概览    │   缩放/平移                        │ ⑦ 机房分布       │
│ ④ 告警等级统计    │                                 │ ⑧ 值班信息       │
├─────────────────┴─────────────────────────────────┴────────────────┤
```

- 布局：CSS Grid `320px 1fr 320px`，顶栏 56px；列内卡片 flex 纵向，超高时列内滚动
- 适配：`html { font-size: calc(100vw/1920*10) }` rem 基准，非 16:9 时上下留黑边
- 卡片壳：统一 `ChartCard`（标题 + 图标 + 刷新时间 + 内容区），暗色玻璃质感

## 4. 节点↔设备 关联与交互设计

### 4.1 关联模型（前端视角）

- 关联存于 `node.properties.deviceId`（编辑器节点设置 → 设备下拉选择），随拓扑版本保存
- 编辑器「节点设置」Tab 增加**关联设备**区块：设备下拉（`GET /api/devices`，显示 `名称(IP)`）、当前关联信息卡（状态/最近告警数）、「查看设备详情」按钮
- 下拉数据缓存（登录时拉一次 + 手动刷新按钮）；节点已关联时下拉默认选中；支持"清除关联"
- 保存时后端校验 deviceId 存在性，422 时编辑器顶部提示缺失清单

### 4.2 大屏节点状态渲染（GraphView）

四态映射（按 `node.properties.deviceId` 查 `/api/topology/active.devices`）：

| 状态 | 判定 | 渲染 |
|---|---|---|
| normal | 设备 status=normal | 正常 3D 图标，无额外效果 |
| warn | 设备 status=warn | 节点底部黄色光晕 + 标签后加 ⚠ |
| alert | 设备 status=alert | 节点红色光晕 + **呼吸灯**（opacity 动画）+ 标签后加 ⚠ |
| unmanaged | 无 deviceId / 设备已删除 | 图标降低透明度（0.65）+ 标签加"未纳管"灰色角标 |

- 状态变更走 WS 增量（`device_status` 消息只重绘受影响节点，不全图重画）
- 分组与状态正交：分组框样式不受成员状态影响（后期可加"分组内告警计数"角标）

### 4.3 设备交互（穿透）

**统一交互入口 = DeviceDrawer（右侧滑出抽屉，宽 400px）**，所有卡片/拓扑点击设备都开它：

```
┌──────────────────────────┐
│ 设备名 · 状态点        ✕  │
│ 类型/IP/机房/责任人        │
│ 被引用: 拓扑v3·家庭节点    │
├──────────────────────────┤
│ [概览] [指标] [告警] [操作] │  ← Tab
│  概览: 最新指标 sparkline   │
│  指标: 时间范围选择 + 大图   │
│  告警: 该设备告警历史+确认   │
│  操作: 重启/重启动按钮      │  ← 本期禁用置灰 + tooltip"待接入"
│       （operator 501 占位） │
├──────────────────────────┤
│        [完整设备页 →]      │  → /devices/:id
└──────────────────────────┘
```

- **已关联节点**：hover 浮层（名称/IP/状态/最近 1 条告警）→ 点击开抽屉
- **未纳管节点**：点击开抽屉的"空态"：提示"该节点未关联设备" + [去编辑器关联] 按钮（跳编辑器并选中该节点）
- **操作 Tab**：本期按钮置灰 + 说明；operator 接入后启用（调 `/api/devices/{id}/actions/{action}`，结果 toast + 写 alert 审计）
- 设备详情页 `/devices/:id`（独立路由）：指标大图（cpu/mem/流量 多 tab）+ 告警历史 + 被引用拓扑入口，本期出骨架

## 5. 拓扑组件移植（apps/web/src/components/topology/）

来源：`/data/project/dct/graph-vis-v1/demo-site/topology/`（已验证的完整实现）。

移植策略——**最小改动**：
1. `graphvis.min.js`、`icons/`（37 张 3D 图标）原样复制到 `lib/`
2. `topology.js`（~1044 行 IIFE）保留 JS 逻辑，拆出纯逻辑为 `engine/topo-core.js`（drawNode/分组/序列化/快照），`GraphView.vue` 用 `onMounted` 调用并持有实例；**不强行 TS 化**（引擎是黑盒闭源，TS 化收益低风险高）
3. 两个使用形态：
   - **GraphView（首页只读）**：禁工具栏编辑项、禁双击连线；开 hover 浮层（设备名/IP/状态/最近告警）、告警着色（`device.status` → 节点描边色 + alert 状态呼吸灯）、点击节点 → 侧滑设备详情抽屉（**穿透入口**）、点击空白清空
   - **GraphEditor（编辑器页）**：全功能（增删/分组/撤销重做/保存），数据源从 localStorage 切为 `POST /api/topology`
4. 大屏展示数据流：`GET /api/topology/active` → canvas + devices 状态映射 → 引擎渲染 → WS 增量更新（device_status / alert 只改节点状态不重画全图）

## 6. 穿透路线

- **本期（入口）**：拓扑/卡片点击 → DeviceDrawer（4.3）；抽屉 → 设备详情页骨架（`/devices/:id`）
- **下期（collector 接入后）**：指标下钻、拓扑分层（机房/业务视图切换）、多拓扑管理、操作能力启用

## 7. 登录页

单页表单（admin/密码）→ JWT 存 `localStorage` → router 守卫；401 自动回登录页。风格与大屏一致（暗色居中卡片）。
